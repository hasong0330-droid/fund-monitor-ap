# 基金买点观察

这是一个可独立运行的 Windows 本地应用，使用 `Python` 运行分析和本地数据服务，并以独立的浏览器应用窗口展示仪表盘，不依赖 Codex 或云端服务器。

当前能力：
- 双击 `run_app.bat` 启动本地应用（适合查看启动日志）。
- 双击 `launch_silent.vbs` 可静默启动，不显示命令行窗口。
- 启动后会自动打开独立应用窗口，地址为 `http://127.0.0.1:8767`；数据和持仓配置保存在本机。
- 如果后台服务已经在运行，重复双击不会重复抓取数据，而是直接重新打开看板窗口。
- 自动尝试获取基金净值、估值和全球指数数据。
- 全球指数实时看板按“腾讯财经 -> 东方财富 -> Yahoo Finance”顺序获取；历史回测额外使用 Nasdaq 公开历史接口补齐长周期指数，全部实时来源失败时缓存仅用于展示最近历史记录，并记录每个来源的失败原因。
- 宏观数据分为两层：市场风险指标（VIX、国债收益率、实际利率、美元和汇率）与经济数据（GDP、CPI、失业率、M2、政策利率、高收益债信用利差）；官方来源与 FRED 失败后，iFinD EDB 可补充已发布的美国 GDP/M2 序列，预测字段会被拒绝，之后才使用其他公开源或缓存。
- 推荐资格按“东方财富费率页（申购状态/日限额）+ 东方财富排名脚本（36个月月末同类百分位）+ 新浪基金概况（类型/基准/全球范围）”交叉核验；任一硬字段缺失时只允许读取完整缓存并关闭推荐。
- 推荐基金不再以单日申购限额、主动管理类型、全球/美股投资范围或近36个月同类排名作为前置筛选条件；这些资格信息仅供参考，实际申购前请核对基金当前状态。
- 基金净值按“基金公司官方接口（可选） -> 东方财富批量/逐只接口 -> iFinD -> pingzhongdata备用接口 -> 本地缓存”顺序获取，并记录每只基金的失败原因。
- 基金历史净值按“基金公司官方接口（可选） -> 东方财富历史接口 -> pingzhongdata备用接口 -> 本地缓存”顺序获取。
- 基金持仓披露会校验披露日期、至少5项有效持仓和权重；抓取失败会保留逐只基金的错误日志，不会静默跳过。
- 重仓企业财报以 SEC Company Facts 为美股优先源，并为美国股票在官方披露失败后增加 iFinD 的已披露财报备用源；报告截止日和至少三项关键指标缺失时自动拒绝。行情与财报分别抓取，任一行情源失败不会再跳过基本面抓取。
- 独立的数据可信度层会校验来源、数据日期、缓存状态和跨源一致性，并在数据不足时关闭交易性结论。
- 数据可信度层单独展示宏观经济覆盖率和市场风险指标覆盖率；核心经济数据不足时，不能把 VIX 或美债行情的完整性当成宏观经济完整性。
- 自动抓取更适合中文财经的真实新闻源，优先使用东方财富和新浪财经；历史点时归档由 iFinD 按美元利率、AI科技、港股互联网、先进制造、汇率和出口管制六个主题分别回填，并按事件指纹去重。
- AI资本开支周期预警独立监控云厂商资本开支、HBM/GPU交期、存储价格、AI商业回报和龙头盈利指引，并按最新披露前十大持仓展示基金AI产业链暴露。
- 对抓取到的财经新闻生成中文摘要，并给出影响标签与基金影响提示。
- 首选实时源失败时会继续尝试备用实时源；只有所有实时源均失败后才读取缓存作历史展示，并关闭分析、预警、买入节点和推荐结论。
- 页面会展示“数据获取审计”：网络预检、每类数据的实时来源优先顺序，以及本次每个来源的成功、失败、熔断或网络跳过原因。
- 网络预检仅作诊断，不会阻止各数据模块按优先级继续尝试实时来源与备用来源。
- 指定基金分析池当前未预置基金，页面保留空状态，可按需要配置后再展示分析。
- 推荐池数量不设上限，也允许为空；只有完整通过申购限额、主动管理、全球或美股投资范围及近36个月同类排名核验的基金才会展示。
- 自动生成简明报告到 `reports` 目录。

指定基金：当前未配置。

运行方式：
1. 确认本机已安装 `Python`。
2. 双击 `run_app.bat`。
3. 程序会生成本地 `HTML` 看板和文本报告，并自动用默认浏览器打开。

协作与个人配置：
- 仓库不包含个人持仓、缓存、报告、日志或任何 API Key。
- 新安装默认没有预加载持仓，可在看板的“配置我的持仓”区域录入。
- 如需本地默认持仓，可复制 `portfolio_defaults.example.py` 为 `portfolio_defaults.py` 后填写；该文件已被 Git 忽略。
- iFinD 和 Investoday 密钥只配置在 Windows 用户环境变量中，不要写入代码或提交记录。
- 开发者可运行 `python -m unittest discover -s tests -v` 验证完整测试集。

可选 iFinD 接入：
- 程序仅读取当前 Windows 用户的 `FUND_MONITOR_IFIND_AUTH_TOKEN` 环境变量，不读取 Codex 技能目录。
- `run_app.bat` 和 `launch_silent.vbs` 会在启动时从当前用户环境中加载该变量；令牌不会写入报告、缓存或日志。
- 当前接入宏观 GDP/M2、美国重仓股已披露财报、基金影响风险新闻和基金公布净值备用源。QDII 基金持仓、推荐资格与重仓股长周期技术趋势仍按各自来源策略执行。

可选基金公司官方源：
- 设置 `FUND_MONITOR_FUND_MANAGER_NAV_URL_TEMPLATE` 后，程序会优先请求基金公司官方净值接口；模板必须包含 `{code}`，例如 `https://provider.example/fund/{code}/nav`。
- 设置 `FUND_MONITOR_FUND_MANAGER_HISTORY_URL_TEMPLATE` 后，程序会优先请求基金公司官方历史净值接口；模板必须包含 `{code}`。
- 接口响应支持 JSON 或 CSV。JSON 可使用 `data`、`records`、`rows`、`result`、`items` 等常见包裹字段；净值字段支持 `nav`、`unit_nav`、`net_value`、`DWJZ`、`单位净值`，日期字段支持 `date`、`nav_date`、`as_of`、`FSRQ`、`净值日期`。
- 官方源只有在返回有效代码、正单位净值和合法日期时才会标记为 `LIVE`；历史接口少于60条记录会自动回退，不会伪造完整历史。
- URL 模板和令牌不会写入报告、缓存或页面。基金公司接口若需要鉴权，应通过网关或本机安全代理提供，避免把密钥写入项目配置。

可选 Investoday MCP：
- 程序读取当前 Windows 用户的 `FUND_MONITOR_INVESTODAY_MCP_API_KEY` 环境变量，不读取 MCP 客户端配置文件。
- MCP 服务地址默认使用 `https://data-api.investoday.net/data/mcp/preset`，如需覆盖可设置 `FUND_MONITOR_INVESTODAY_MCP_URL`。
- 当前接入 `list_news`，用于基金影响新闻和 AI 资本开支周期预警；Investoday 当前提供的是 ETF 实时行情和研究数据，不能替代开放式基金单位净值或历史净值来源。
- `run_app.bat` 和 `launch_silent.vbs` 会在启动时加载该环境变量；密钥不会写入代码、报告、缓存或页面。

浏览器辅助采集：
- 当浏览器可以打开天天基金/基金公司详情页、但 Python 直连被系统拦截时，可在浏览器中将详情页保存为 HTML，再导入浏览器观察到的公布净值。
- 导入命令示例：`python browser_source.py --html 016702 D:\\Downloads\\016702.html --output cache\\browser_fund_quotes.json`。
- 解析器只接受页面中明确标注的“单位净值（日期）”，并校验正单位净值；估算净值、缺少日期或无法确认代码的页面会被拒绝。
- 导入后的来源标记为 `browser-fund-page`，会进入统一实时来源审计；页面保存时间和公布净值日期都会保留。
- 浏览器辅助采集目前用于最新公布净值。历史净值仍需使用基金历史页面或官方历史接口，少于60条记录时不会进入完整分析。

网络诊断与代理：
- 每次运行会记录 DNS、TCP、iFinD 配置状态和官方源配置状态。DNS 成功但 TCP 失败时，报告会明确标记为网络出口/防火墙问题。
- 如所在网络要求代理，可在启动程序前设置 `HTTPS_PROXY` 和 `HTTP_PROXY`；代理只用于联网请求，不会改变缓存和交易资格规则。
- 若诊断显示 `WinError 10013`，可右键以管理员身份运行 `repair_network_access.ps1`（或在 PowerShell 执行 `Start-Process powershell -Verb RunAs -ArgumentList '-ExecutionPolicy Bypass -File .\repair_network_access.ps1'`）。脚本只为项目实际使用的 Python 和 Chrome 添加出站 TCP 443 允许规则，并将结果写入 `logs/network_repair_result.txt`；不会关闭防火墙。若管理员测试成功而普通进程仍失败，通常是公司安全软件、VPN 或系统上游策略拦截，需要网络管理员放行。
- `cache`、`baseline` 仍只能用于展示或保守回退，不能提升实时数据质量，也不能生成强买或精确减持结论。

推荐入口：
- `launch_silent.vbs`：日常使用，双击即可启动本地应用。
- `run_app.bat`：需要查看启动过程或排查网络问题时使用。
- 命令行也可以使用 `python app.py --desktop` 启动同样的本地应用模式。

目录说明：
- `cache`：缓存基金、指数和新闻数据。
- `reports`：生成的 `HTML` 看板和文本报告。
- `backtest_samples`：模型回测使用的净值、指数、季度持仓和逐日事件样本。
- `logs`：预留日志目录。

模型回测：
1. 首次运行 `python backtest_model.py`，联网建立指数和季度持仓样本。
2. 后续运行 `python backtest_model.py --use-cache`，使用已保存样本复现结果。
3. 在 `reports/model_backtest_report.html` 查看回测结论。


数据有效期：QDII基金净值3天、A股基金净值2天、全球指数1天、影响新闻2天、基金持仓披露150天；GDP约145个交易日、CPI/就业/政策利率约50个交易日、M2约65个交易日、信用利差约5个交易日。可信实时来源在交易日历允许的正常披露延迟内可进入保守分析，其余缓存或过期数据不进入分析流程。

决策闸门：
- `READY`（可用于分析）：关键数据完整、来源和时效均通过，可生成动态买入节点。
- `LIMITED`（保守分析）：仅允许可信实时来源的正常交易日或QDII披露延迟，生成收窄后的保守区间，强买信号关闭。
- `BLOCKED`（禁止判断）：关键净值、历史净值、对应指数、宏观数据、持仓披露、重仓财报或基金影响新闻未通过来源、时效和完整性校验；不显示买入价格，也不输出持仓操作或市场方向结论。

运行 `python -m unittest discover -s tests -v` 可复核净值覆盖、缓存降级、过期阻断、指数阻断、推荐资格多源核验、月末排名抽样和评分边界。

- 如果后续需要，可以继续补充持仓明细抓取、基金筛选规则增强，以及打包成 `.exe`。
